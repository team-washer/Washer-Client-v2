# 로그인 화면 반응형 설계

## 의도

작은 휴대폰 화면에서 로그인 카드가 고정 폭 때문에 좌우로 잘리지 않도록 하고, 넓은 화면에서는 현재의 시각적 비율과 최대 폭을 유지한다.

## 목표

- 로그인 카드가 viewport 안에서 항상 보인다.
- 카드의 좌우 여백이 작은 화면에서도 유지된다.
- 로고와 OAuth 로그인 버튼이 카드 너비에 맞춰 자연스럽게 줄어든다.
- 데스크톱의 기존 최대 폭과 스타일은 유지한다.

## 비목표

- OAuth 인증 흐름이나 네트워크 재시도 정책 변경
- 로그인 문구·색상·브랜드 자산 변경
- 앱 전체의 다른 페이지 반응형 개편

## 접근 방법

1. 고정 폭 카드만 유지: 구현은 가장 작지만 좁은 화면에서 overflow가 계속된다.
2. **반응형 최대 폭 적용(선택)**: 카드에 `w-full max-w-110`을 적용하고 부모에 전체 너비를 제공한다. 기존 데스크톱 폭은 유지하면서 모바일에서 자동 축소된다.
3. 화면별 별도 레이아웃: 모바일/데스크톱 마크업을 나누면 제어력은 높지만 중복과 유지보수 비용이 커진다.

## 구현 결정

- `AuthLayout`의 콘텐츠 영역은 `w-full`을 사용하고, 작은 화면의 안전한 좌우 여백은 `px-4`, `sm` 이상에서는 `px-6`으로 적용한다.
- `SignInForm` 카드와 앱 다운로드 카드 모두 `w-full max-w-110` 패턴으로 통일한다.
- 카드 내부 수평 패딩은 모바일에서 조금 줄이고 `sm` 이상에서 기존 여백을 유지한다.
- 기존 OAuth 컴포넌트의 동작은 변경하지 않는다.

## 검증

- 반응형 클래스가 로그인 화면에 적용되어 있는지 회귀 테스트로 확인한다.
- 타입 검사와 프로덕션 빌드를 실행한다.
- 320px 폭에서 overflow가 생기지 않는지 브라우저 또는 렌더링 결과로 확인한다.
